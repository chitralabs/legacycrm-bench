## Runner design (to be implemented as 03_source_code/runner/ before P1)

- **Sandboxed candidate execution (mandatory; Amendment A1).** Model-generated code is
  untrusted. Candidate acceptance-test runs execute inside an isolated environment
  (container or unprivileged sandbox) with: network access denied; a scrubbed environment
  (explicit whitelist — no API keys or user environment); CPU/memory/process rlimits; the
  case mounted as a **sanitized copy** containing only `tests/` and the candidate solution —
  never `reference/`, `GROUND_TRUTH.md`, or other cases — so candidate code cannot read the
  oracle or ground truth at runtime; and read-only mounts for everything but the scratch dir.
  The sandbox implementation and its verification (a probe candidate that attempts network,
  environment, and oracle reads must be caught) are release-gated before P1.
- Reads case dirs; builds prompts from templates in `04_experiments/prompts/` (versioned).
- Extracts deliverable files from model output via explicit file-block markers
  (```file:migrated.py``` fences specified in the prompt); saves candidate solution dirs under
  `04_experiments/candidate_solutions/<run_id>/<CASE_ID>/`.
- Invokes `harness/run_case.py` per candidate; writes JSONL to `05_results/model_runs/`.
- Records per call: model ID string, provider, params, prompt SHA-256, response SHA-256,
  usage tokens, latency, timestamp, retry count.
- C4 repair loop: redacts assertion expected values via `runner/redact_failures.py` before
  feeding failures back; max 2 repairs; every intermediate output kept.

## Analysis (to be implemented as 03_source_code/analysis/model_analysis.py)

- Wilson 95% CIs per (model, condition) on case all-pass and test pass proportions.
- Paired bootstrap (10k resamples over cases) for condition deltas; McNemar exact tests;
  Holm–Bonferroni. pass^k for k=1..5. Property-class breakdowns. Cost/latency tables.
- All tables/figures generated by script from raw JSONL only.

## Preservation-property tagging

RQ2 requires an explicit per-test tag map, `05_results/test_tags.csv`, listing every test
nodeid with one property class (functional / ordering-rounding / security / privacy / audit /
completeness-hallucination). `analysis/tag_tests.py` (to be implemented before P1) generates a
DRAFT map from name-token heuristics, but the internal review showed pure token matching
misclassifies tests (e.g., `opted_out` vs `optout`), so the draft is only a starting point:
every row must be manually reviewed and corrected, the reviewed map is frozen and
version-controlled before P1, and analysis reads only the frozen map. The review is a
checklist item in FINAL_SUBMISSION_CHECKLIST.md.

## Stop rules

- Hard budget cap set at authorization time; runner halts when projected spend of the next call
  exceeds remaining cap.
- Any evidence of oracle leakage in C4 (expected values visible in redacted output) → halt C4,
  fix redaction, discard and re-run the affected condition.
