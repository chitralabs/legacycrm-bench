# LegacyCRM-Bench — OJ-CS Submission Project (v1)

**Paper (in preparation):** *LegacyCRM-Bench: A Reproducible Benchmark for Evaluating LLM-Assisted Migration of Enterprise CRM Customizations*
**Target venue:** IEEE Open Journal of the Computer Society (OJ-CS)
**Project started:** 2026-09-01
**Status:** see `10_submission_package/SUBMISSION_READINESS_REPORT.md` (authoritative readiness verdict)

## Integrity commitments

- Every reported number traces to a dataset record, raw output, log, executable test, or documented
  calculation, via `09_peer_review_audit/CLAIM_EVIDENCE_LEDGER.csv`.
- No fabricated model outputs, results, human feedback, or references. All references verified in
  `01_literature/REFERENCE_VERIFICATION.csv`.
- All benchmark artifacts are synthetic and transparently generated (no employer/customer/proprietary
  material). Provenance is documented per case and in the dataset card.
- LLM evaluation experiments are **not** run until a dry-run cost projection exists and paid API use
  is explicitly authorized (`04_experiments/ESTIMATED_COSTS.md`).

## Reproduction workflow

```bash
cd v1
python3 -m venv .venv && .venv/bin/pip install -r 03_source_code/requirements.txt
# 1. Regenerate seed data (deterministic, seeded):
.venv/bin/python 03_source_code/generate_seed_data.py
# 2. Validate benchmark case structure:
.venv/bin/python 03_source_code/harness/validate_cases.py
# 3. Ground-truth validation (reference solutions vs. acceptance tests):
.venv/bin/python 03_source_code/harness/run_all.py --solution reference --out 05_results/reference_validation.jsonl
# 4. Null-baseline discriminative check (empty solutions must score ~0):
.venv/bin/python 03_source_code/harness/run_all.py --solution null --out 05_results/null_baseline.jsonl
# 5. Mutation sensitivity analysis of the test suites:
.venv/bin/python 03_source_code/harness/mutation_check.py --out 05_results/mutation_results.jsonl
# 6. Aggregate results into tables:
.venv/bin/python 03_source_code/analysis/aggregate.py
```

LLM-condition experiments (zero-shot, structured prompting, etc.) are specified in
`04_experiments/EXPERIMENT_PLAN.md` and require API authorization before execution.
